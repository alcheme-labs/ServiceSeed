# 宿主能力与可选 Agent Bridge 接入

中文译文 | [English](host-integration.md)

实施或检查宿主向维护 Agent 提供能力的路径时阅读。本文件是 [ServiceSeed 协议](protocol.zh-CN.md)的操作映射，不是第二套规范接口。复用已有宿主选择请求/响应形式、入口与持久化。表格不要求每行一个工具、固定方法名，也不要求每个任务提供全部方法。

## 提供实际操作能力，而不只是连接 Agent

| 本次任务需要 | 宿主在授权内提供什么 | 实际负责方落实与返回什么 |
| --- | --- | --- |
| 观察与诊断 | 服务身份/委托/契约与验收责任；资源/依赖及语义；活动实现/版本；触发、观测状态与未完成操作。提供真实操作说明、入口、输入输出、限制及恢复语义 | 披露前核验观察与模型可见权限。事实带来源/版本/时点；未知保持未知。对外描述不泄露内部上下文 |
| 创建/提出修改 | 声明与可执行候选、保持的契约、基准版本及依赖条件的真实提交入口。初次创建明确负责人和认可的目标/规则 | 保存候选身份/内容及真实提交结果。提交不新增资源权或启用权；若宿主实际采用获准文件提交，也可复用 |
| 验证 | 已有受控执行/检查入口，采用负责人认可判据、候选和依赖条件；可取得实际结果/证据 | 落实候选执行的数据、网络、凭据和副作用限制，保留验证对应的候选/判据/条件。Agent 生成测试可以补充，不能替换或削弱认可判据 |
| 启用、回退或停用 | 向已有发布负责方请求，关联候选/证据、基准/契约/条件，以及提交前已知且可恢复的操作关联 | 重验现行维护权、证据、当前基准与依赖。重复/并发提交保持原效果。返回真实启用版本与操作结果，消费者验证和当前可用性分别表达 |
| 描述、绑定及调用依赖 | 获准可信描述、共同契约/绑定、已有授权证明/引用、实际调用和消费者结果；关系归属和可恢复的已接受选择 | 双方检查身份、自身/受托主体、动作/范围、执行与交付权。绑定不造授权，拒绝不支持的必需能力和不兼容契约；确认受影响承诺后才称可用 |
| 查询/接续/报告 | 按现行查询权定位原操作、真实状态/结果和获准接续；通知在范围内时使用配置好的目标及投递结果 | 查询不重做效果。未知保持未知，撤销查询权不改写过去效果。按恢复约定和当前权限接续，本地日志不等于投递 |

这些能力可以由应用工具、函数、CLI、上下文注入加受控宿主执行，或平台已有发布 API 提供。只能返回候选的 Agent 也可参与，由宿主在其授权控制下验证和启用；任务须准确说明各动作由谁完成。不能为补上受控入口的缺失就直接给予 Agent 生产代码写权。

用户已授权实施而所选宿主缺少必要能力时，在原负责方补最小入口。超出本次范围则说明具体缺边并交付已支持部分。不新增另一套授权、发布、操作状态或业务结果权威。本文件不强制任意代码执行或新工具。

## Bridge 负责什么，ServiceSeed 仍须补什么

[Agent Bridge Spec](https://github.com/alcheme-labs/agent-bridge-spec)定义通用应用与 Agent 接入，其 `agent-bridge-integration` Skill 可指导适用连接：

- **角色 A：** 服务宿主发起应用范围内的 Agent 任务/会话，包括获准后台任务。
- **角色 B：** 已有 Agent 调用服务宿主获准方法；不要求应用控制 Agent 的整个会话。

按对应规范的真实能力及绑定，处理任务/上下文交付、输出、工具、交互、身份/披露、停止/限制和恢复。Agent 任务 ID 或工具传输成功不自动等于服务持久操作关联或业务成功。必要时由绑定将其连到原效果负责方，不据此新增结果数据库。取消模型执行不撤销已发布候选或已发生的业务效果。

ServiceSeed 补齐表中的服务专属信息与行为：接受的服务承诺、当前实现与依赖语义、委托修改范围、候选/基准关联、认可验收、启用前提、服务关系检查、重启接续和真实消费者结果确认。Bridge 的通用方法结构不能替我们确定这些业务事实。Bridge 没有具体方法时也在这里补清定义，再映射到真实宿主能力，不能假装它已内置；也不为让 Bridge 显得完备而把业务责任搬进去。

已核对基线见 [compatibility.json](../compatibility.json)：公开规范 draft 0.3 与 [Skill 0.1.0](https://github.com/alcheme-labs/agent-bridge-spec/releases/tag/agent-bridge-integration-v0.1.0)，于 2026-11-13 按记录的提交核对。这是文档核对，不代表已有可执行 SDK 或运行兼容证明。已安装匹配 Bridge Skill 时，解析实际目录并遵循其保留完整仓库的安装要求；否则在获准时取得匹配的公开版本，不编造安装包。没有 Bridge 不妨碍使用满足 ServiceSeed 要求的原生连接。

## 独立版本

ServiceSeed 协议、本 Skill、Bridge 规范、Bridge Skill 及实现包各有发布周期，版本号不锁步。[VERSION](../VERSION) 是本 Skill 版本的唯一数值来源，随包协议固定此版采用的规范。Bridge 引用是核对过的文档基线，不是已验证的 semver 范围或运行依赖。

选择或升级 Bridge 时，检查本次 A/B 角色、实际运行环境、绑定、任务/上下文/输出、身份与披露、必需交互/限制和效果恢复。在服务项目已有接入记录中保存选定版本及真实证据。这些发生实质变化时，采用前重验受影响路径。版本更高不证明兼容，版本不变也不保证所有适配器可用。未来有独立验证范围后，应与本次仅文档参考分别表达。

仅在实际使用 Bridge Skill 时运行其自带检查器，让它负责自身提醒和状态。本 Skill 检查器只关注 ServiceSeed 发布，不另造 Bridge 更新器或重置其已提醒/忽略决定。
