# 创建和维护 ServiceSeed 服务

中文译文 | [English](SKILL.md)

创建能在授权内调整实现、同时保持调用方承诺的服务。本 Skill 将[协议](references/protocol.zh-CN.md)落实为工作指引，不是另一份协议、已运行的宿主或授权。协议译文差异依据中文原文核对。[VERSION](VERSION) 标识 Skill 版本，[compatibility.json](compatibility.json) 标识协议版本与可选 Bridge 参考。本文件是英文 Skill 的对应译文，不作为第二个自动发现入口。

同一流程适用于 FDE（Forward Deployed Engineering，面向客户业务的工程交付）所交付的服务，以及个人服务空间。FDE 场景明确客户认可的承诺、资源负责方与维护委托；个人服务明确所有者及获准调用者、数据用途、模型披露与维护者。两者是一份协议的应用，不另设规范分支或任务模板；FDE 身份或个人所有权均不自动授予其他负责方控制的资源权限。

## 从实际任务开始

1. 先读随包协议的范围、核心与[原子服务要求](references/protocol.zh-CN.md#atomic-service)，再读本次适用章节。任务中一致采用此版本，不静默换用新草案。区分用户请求的是讨论、评审、创建还是维护。
2. 明确用户目标、获认可的业务规则与验收、已有服务/契约、获准资源与模型可见范围、实际宿主入口，以及授权、状态、验证和发布的负责方。复用已有设施。只询问影响本次结果的缺失决定或授权，不从字段名编造业务含义。
3. 网络及 Python 3.9+ 可用时运行 `python3 <skill-directory>/scripts/check_updates.py check`。只有 `notify: true` 才自动提醒；按[更新处理](references/updates.zh-CN.md)执行，包括缓存提醒和展示后记录。缺少更新源或检查失败不证明当前版本最新，也不阻断服务任务。没有持久状态时不承诺跨会话去重，也不每次使用都重复提醒。本 Skill 不创建调度任务。

## 确认宿主实际具备的能力

创建服务、接入 Agent 或诊断维护能力缺失时，阅读[宿主能力与 Agent 接入](references/host-integration.zh-CN.md)。将所需动作对应到已有真实工具、函数、CLI 或受控入口及其实际权限。上下文可以注入或查询，不要求固定工具数、MCP、注册平台或上下文数据库。

Agent 需要获准的职责、资源/当前实现、可用操作和本次触发/状态/未完成结果信息；这些事实来自已有声明、授权与持久状态负责方。对外能力可见性、调用权、内部维护可见性、向模型披露与修改权分别处理。在披露、执行、启用和交付处重验当前权限，上下文不授予权限。

Agent 连接/会话接入可按需使用 [Agent Bridge Spec](https://github.com/alcheme-labs/agent-bridge-spec) 中实际可用的 `agent-bridge-integration` Skill，读取相应规范并选择适用角色/绑定。不可用时使用已有且获准的原生适配方式，或说明缺少的接入；不编造 SDK、不调用不存在的 Skill，也不要求所有服务使用 Bridge。Bridge 不提供 ServiceSeed 的服务契约、维护委托、候选验证/启用、服务调用关系或业务效果权威。通用 Agent 工具即使可用，也要在本 Skill 中完成这些映射。版本及职责边界见参考文档。

## 创建或变更服务

- 根据目标和认可的规则，产出选定宿主真正可消费的声明：稳定实例身份和负责人；能力含义、契约版本与验收依据；实现/资源/依赖；调用方、运行与维护分别授权；状态/结果负责方；维护触发、限制及启用/恢复路径。明确缺失或未绑定依赖。创建不局限于预设任务模板目录。
- 按宿主支持的执行形式生成候选。宿主限制属于本次交付边界，不是协议要求。统一声明编码及服务互通线格式尚未定型；记录双方实际采用的映射并验证，不能自创一份后称其为标准。
- 用户或有权负责人确定初始承诺与权限。接受后，维护保持已接受契约。不兼容业务变化另行提交有权各方决定，不能为使测试通过而重释契约。
- 候选及证据对应具体内容/引用、基准实现、接受的契约及相关依赖条件。负责人提供或认可判据，生成 Agent 不能修改判据或自证成功。获准样例和预期结果可以公开，隐藏测试可选。在资源和副作用限制内请求宿主真实验证。
- 通过已有发布负责方请求启用，由其重新检查现行委托、候选/证据、基准与相关依赖。过时候选不能覆盖新版本。首次可能产生效果的提交前，通过宿主已有机制保存可恢复关联。提交候选权不等于启用权。
- 沿约定调用路径确认真实效果与消费者结果。区分声明已生成、候选已验证、已启用、消费者已验证及当前可用。复用有效真实响应/证据，不为验证重复产生业务效果。缺少适用宿主或验证入口时，交付声明/候选并指出具体缺边，不能称服务已运行或合规；仅在用户授权范围内实现缺边。

## 连接独立创建的服务

遵循协议的[交互约定](references/protocol.zh-CN.md#minimum-interaction)和[最小流程](references/protocol.zh-CN.md#minimum-flow)。取得可信且获准的描述，识别双方及自身/受托执行主体，选择共同支持的契约、绑定和必需特性，通过已有授权方取得或使用权限。绑定不产生权限，也不开放提供方内部信息。

由原负责方保存/复用所接受关系，沿真实授权调用确认受影响承诺及消费者结果，通过后才确认可用。重启恢复已接受身份/契约/绑定与未完成工作，并核验当前权限。未知必需能力、不兼容含义或缺少共同绑定意味着兼容关系未建立，不能据此猜测或静默换路。组合保持数据使用、披露、缓存与转授限制。

## 维护与恢复

根据真实触发、可信依赖语义、当前实现/状态与已有操作结果诊断变化。普通调用继续采用仍获准且可履约的实现，模型无需逐次介入。生成新候选并复用受控验证/启用路径。缺少关键语义时由其负责人补充，不猜测修复。

响应丢失、启用中断、重试或重启时遵循[操作恢复](references/protocol.zh-CN.md#operation-recovery)。凭首次提交前已有的关联定位原效果负责方，区分未完成、已生效、确认未生效与未知。复用已生效结果，仅在约定防重复效果能力及现行授权下重试。查询被拒、超时、记录缺失/过期或后来活动版本不同，都不能证明原操作失败。不通过更换标识、后端或执行者绕过未知。查询需要当前披露权，不能续权或重新执行效果。

回退仍需当前权限和兼容/验收，代码回退不等于数据恢复。维护失败时保留仍获准且可履约的实现，否则报告不可用及需要负责人作出的决定。通知投递与本地日志分别记录。相关消费者结果尚未确认时，不能报告恢复。

## 验证与交付

使用真实入口及与影响相称的已有检查。创建/维护验证获认可业务行为、拒绝越权访问/模型披露、受控启用和消费者结果。调用关系、持久操作或恢复在本次范围内时，补充重启、步骤间撤权、过时/并发候选、重复提交和响应丢失后确认。复用仍有效证据，说明确实不适用的检查；仅顺利样例或结构校验不充分。

实施任务交付声明/实现及真实运行、使用、维护入口，以及简明证据和剩余边界。区分文档、源码检查、已执行行为和独立实现互通。加载 Skill、连接 Bridge 或生成代码本身均不证明这些结果。安全拒绝属于正确处理，不等于恢复成功。

可选能力保持可选：递归包装/组合不固定层型；没有任务要求就不新增共享上下文、订阅、同步、收费、复制、网络或账本。实际提供的能力仍承担对应协议义务。本 Skill 不在用户任务授权之外授予付费模型调用、生产写入、部署、发布或自动升级权限。

除非用户明确要求其他语言，按照用户使用的语言回复。
